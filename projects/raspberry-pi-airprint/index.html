01 / The idea

Keep the printer.
Change how it connects.

My HP LaserJet P1005 did not have native AirPrint. I used a Raspberry Pi Zero to add the network-printing side, rather than asking the printer to do something it was never built to do.

The Pi sits between the USB printer and the home network. It receives print jobs, handles the printer connection, and makes the printer available wirelessly. I got Wi-Fi and AirPrint working with this setup.

AirPrint, not AirPlay.

AirPrint is for printing from Apple devices. The printer still connects to the Pi by USB; the Pi is the network bridge.

For a similar build, also plan for

  • A microSD card with an OS compatible with your Pi.
  • A suitable power supply and a USB data connection to the printer.
  • A connection from the Pi to your home network.

Check which Zero you have before buying parts. The original Zero has no built-in Wi-Fi; wireless models or a compatible adapter provide it. The exact Zero variant and adapter details are not recorded here.

Three separate jobs.

04 / Build overview

How the pieces fit together.

This is a record of the project and a high-level path for a similar build, not a copy-and-paste installation guide.

  1. Get the Pi onto the network

    Install a compatible Raspberry Pi OS and make sure the Pi can reach your network and download packages. The original setup had networking problems before the printing work could begin.

  2. Bring up the print server

    Install and start CUPS, then confirm its administration interface works. Keep administration authenticated and limited to your trusted local network.

  3. Add the USB printer

    Connect the P1005 to the Pi, select the actual USB device in CUPS, and configure a compatible driver. Prove that a local test page prints before debugging wireless discovery.

  4. Share and discover

    Enable sharing for the printer and configure local discovery. CUPS sharing and Bonjour-compatible discovery are separate parts of the same path.

  5. Test from the devices you use

    Check printing from the Mac and the iPhone or iPad on the same home network. Then check again after restarting the Pi and power-cycling the printer.

05 / What to watch for

The details matter.

Discovery is not the same as printing

A printer appearing in a list does not prove that its driver can print. Test the USB queue first, then the network connection.

Check firmware after a cold start

The P1005 has a firmware-loading requirement. Verify the chosen driver’s firmware setup and test after switching the printer off and back on. Do not assume installing a package alone has covered it.

OpenPrinting’s P1005 firmware-loading configuration

Keep it on the home network

A home print server does not need to be exposed to the public internet. Keep credentials private, keep the Pi updated, and avoid router port forwarding for the print service.

The result

One less reason to replace a printer.

The Pi added Wi-Fi and AirPrint to hardware that did not have them. It was a connectivity upgrade, not a fix for worn printer parts or faded output.
